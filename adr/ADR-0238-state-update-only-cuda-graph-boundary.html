ADR-0238 State-update-only CUDA graph boundary¶

语言: English

  • Status: Rejected / no-go / historical pre-registration

  • Date: 2026-10-14; closeout 2026-10-15

  • Owners: UniLab Manager runtime; UniSim backend contract owner

  • Driving issue: #2338

  • Scope: historical no-reset Manager state-update pre-registration; no active runtime contract

  • Supersedes: None

  • Superseded by: None. The residual public graph lifecycle/completion contract was removed by #2359; eager ordered completion is operation-neutral.

Context¶

Issue #2311 closed no-go at its complete K=1 collector boundary. The evidence does not show that Manager state-update compute itself is impossible to capture; it shows that embedding MJWarp physics replay and reset publication inside a caller-owned outer graph is not valid with the available public boundaries. #2338 therefore defines a narrower candidate without changing #2311’s historical result or support claim.

The existing runtime already distinguishes the useful pieces:

  • ManagerBasedRlEnv.update_state() publishes stable post-physics qpos, qvel, and sensor views through the public SceneTensorReadPlan;

  • SimBackend already exposes public tensor lifecycle capabilities, step completion receipts, deferred validation, and graph lifecycle snapshots;

  • Manager owners now retain persistent reward, observation-noise, command, motion-sampler, and validation carriers across eager steps;

  • #2338 U1 extracts the fixed eager update body behind named owner methods and audits only that narrower boundary.

Decision¶

This decision is rejected. Issue #2358 found that the measured benefit depended on disabling or bypassing real semantic boundaries, while graph safety would permanently constrain every reward, observation, and command term author. The graph-only preflight, manifest, runtime, benchmark, and static-audit surfaces were removed without compatibility aliases or eager fallback. The follow-up #2359 also removed the public graph lifecycle/capture identity and replaced the surviving ordered receipt boundary with the neutral completion contract.

The original candidate is retained below as historical pre-registration evidence. It is not an implementation plan, a support claim, or a successor boundary. Commands, APIs, test names, and manifests named in those historical sections no longer exist; the neutral hot-path audit that survived the initial removal was itself deleted under #2363 in favor of observable-contract tests.

Capture only the UniLab-owned, fixed-shape, no-reset Manager state-update publication body after the backend step completion boundary. Policy inference, action/control processing, physics, packed reset, post-reset observation, semantic publication, replay ingress, and learner work stay outside.

Exact boundary¶

Ordered outside the update graph:

  1. learner policy inference and action transport;

  2. action processing and control transform;

  3. backend step_tensor() / MJWarp physics replay;

  4. backend step completion receipt;

  5. update graph replay;

  6. update completion receipt;

  7. external fixed-width reset orchestration and post-reset publication;

  8. semantic logs, metrics, recorders, replay ingress, and learner updates.

Inside the first candidate:

  • episode-step device carrier update;

  • termination and timeout compute;

  • terminated/truncated/reset-mask carrier publication;

  • reward vector and reward-component carrier compute;

  • metric compute that only writes persistent carriers;

  • command dt, command update, and command post-compute;

  • observation groups, history, noise, and mapping;

  • persistent public observation/reward/done output carrier writes;

  • persistent owner finite-verdict carrier writes.

The first candidate is the no-reset publication body. Reset preparation and post-reset observations are not captured.

A dedicated static audit recorded the narrow update-body classifications above. Its eager-only clone classifications are explicit, not unclassified graph violations. That audit was deleted together with the graph contracts by the #2363 removal; the surviving neutral hot-path audit is listed under Evidence In Repo.

Owner mode and manifests¶

#2338 must introduce a distinct cold-path owner mode:

env_update_graph = disabled | eager | graph

It must not reuse or reinterpret collector_graph. graph is only a request. A backend physics graph, physics READY lifecycle, or physics preflight verdict never proves that the update graph is READY. Unsupported capabilities, malformed manifests, owner rejection, or failed real capture fail closed. Explicit eager fallback, if later allowed, is separately selected, counted, reason-bearing, and cannot silently enable another mode.

The manifest needs its own contract version, capture identity, state, requested and enabled flags, disable/invalidation reason, replay counters, backend step receipt identity, update completion identity, RNG state/draw versions, and carrier-layout evidence.

Backend-first public preflight¶

Before UniLab consumes it, SimBackend must expose an update-specific public preflight boundary, distinct from the existing generic graph-candidate preflight. It must fail closed unless all of the following are true:

  • public stable full-width qpos/qvel and requested sensor views exist;

  • public step completion publication exists;

  • selected Torch device is CUDA-resident and supported;

  • declared stream/event ownership allows ordered execution after the backend step receipt;

  • allocator readiness can be observed through the public boundary;

  • backend-private probing is not required;

  • deferred validation and persistent finite verdicts are supported.

The verdict must name the update boundary. It cannot be inferred from backend physics graph enablement. A later backend-first completion-token extension for an env_update operation would follow the same rule; the backend step receipt is an ordering input and must never be relabeled as update completion evidence. (The graph completion-token API named in the original pre-registration was deleted by the #2363 removal.)

Carrier contract¶

Before warmup and capture, every input/output address, shape, dtype, and device is fixed:

  • backend qpos/qvel and named sensor stable views;

  • episode-step carrier;

  • command state and motion frame/end state when command compute is captured;

  • command dt;

  • observation history and noise carriers;

  • reward vector and reward components;

  • terminated, truncated, reset mask, and public done carriers;

  • observation-group public carriers;

  • owner finite-verdict carriers;

  • RNG evidence state and versions.

Carrier drift invalidates the graph. No graph-mode path may recover layout by allocating replacement carriers.

Stream and completion ordering¶

The only accepted lifecycle is:

policy action (outside)
→ action/control transform (outside)
→ backend step graph replay
→ backend step completion receipt
→ ordered update-stream wait
→ update graph replay
→ update completion event/receipt
→ external reset/publication/ingress

The update graph publishes independent completion evidence with its own capture identity and sequence. The backend receipt proves physics/state publication ordering only. A stale backend receipt, mismatched capture identity, or update replay failure rejects the transition and fails closed or executes the pre-declared explicit fallback policy.

RNG and warmup¶

If command/noise compute consumes RNG, the draw order is recorded before capture. The complete pre-warmup semantic state is snapshotted; warmup may advance device execution but cannot silently advance Python-side RNG accounting or semantic state. Capture warmup restores the semantic state before the first production replay unless the recorded draw is intentionally part of that transition. State and draw versions enter every semantic comparison and run manifest. Failed replay rolls back to the recorded boundary.

Reset handling¶

The update graph may publish a reset mask, but reset remains external. The external orchestrator consumes the fixed-width mask and must not branch on a host bool mask read. Empty, partial, and full masks remain eager-equivalent and exercise the same fixed-width reset boundary.

Pre-registered Gate U¶

Semantic acceptance is new for #2338 and does not inherit #2311 Gate S.

It compares eager update execution with update-graph execution over:

  • every observation group;

  • observations containing history and configured noise;

  • reward vector and all reward components;

  • command state, motion frame/end state, and command metrics;

  • terminated, truncated, and reset masks;

  • every public validation verdict;

  • episode/reset counters;

  • RNG state and state/draw versions;

  • capture warmup followed by replay;

  • repeated deterministic replay;

  • stale receipt/capture rejection;

  • empty, partial, and full reset masks;

  • fixed carrier addresses/shapes/dtypes/devices across warmup, capture, and replays.

Gate U additionally requires zero update-body static-audit violations and runtime evidence that allocator statistics do not change across capture or repeated replays. Throughput can never override this gate.

Pre-registered Gate UP¶

Performance acceptance compares fresh-process eager versus update-graph paths under both null and MPS execution. Each arm uses at least three paired, interleaved repeats. Runs record both:

  • update-stage attributable timing; and

  • end-to-end run_summary.json:tail_env_steps_per_sec.

The default workload is the canonical FlashSAC / G1 motion tracking / MJWarp owner configuration with N=2048, actor/critic observation groups, all reward components, algo.seed=1, env.seed=1, n_step=1, and fixed null/MPS orchestration. The final U5 decision must freeze exact workload shape, seed, iterations, warmup/replay counts, report interval, host/driver/runtime versions, and threshold before measurements are observed.

The initial threshold to beat is at least +10% median improvement in update-stage attributable timing in every execution arm, with no end-to-end regression and all safety observations valid. A performance no-go is valid and must not become a support claim.

Stable Contracts¶

  • env_update_graph is distinct from collector_graph;

  • backend update preflight is public and update-specific;

  • update completion is independent from backend step completion;

  • reset, replay ingress, and learner/inference work remain outside the first graph;

  • graph mode fails closed until real capture succeeds;

  • no backend-private probing or backend-name dispatch;

  • RNG state/draw evidence and carrier layouts are manifest data;

  • no UniLab release or graph support claim is authorized by this ADR.

Alternatives Considered¶

  • Reuse collector_graph: rejected as misleading because #2311 named and validated a complete collector boundary, not this no-reset update-only body.

  • Reuse generic backend graph preflight: rejected because physics-graph readiness cannot prove update-boundary readiness.

  • Capture reset preparation too: rejected as a separate future decision and contrary to the first #2338 candidate.

  • No update graph: remains valid if U2/U3/U4/U5 find a structural barrier or performance no-go; independently valuable eager extraction and carrier work remains useful.

Consequences¶

  • The state-update-only graph route is rejected; no caller-owned update graph, preflight, manifest, replay, or fallback API is authorized.

  • Eager execution remains the sole Manager state-update path.

  • Independently useful eager work remains: update-body extraction, persistent carriers, deferred validation publication, completion receipts, and the public SceneTensorReadPlan.

  • The hot-path hygiene audit stayed neutral and was later removed under #2363; allocation/host-sync regressions are covered by observable-contract tests and the benchmark smoke gate.

  • Backend-owned physics graphs and learner-owned CUDA graphs are unrelated boundaries and are not affected by this rejection.
