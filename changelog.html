Changelog / 变更日志¶

UniLab follows Semantic Versioning. This shared page records notable PyPI releases and unreleased changes in English and Chinese; release dates are PyPI upload dates. For the complete commit history, see the UniLab repository.

UniLab 遵循语义化版本。本共享页面以中英文记录重要的 PyPI 版本变更与未发布变更；发布日期采用 PyPI 上传日期。完整提交历史请参阅 UniLab 仓库。

Unreleased / 未发布¶

Breaking changes / 破坏性变更¶

  • training.collector_tensor_device, manager_torch_device, env.tensor_runtime, and env.tensor_runtime_device are removed. Use training.sim_carrier_device (routed to env.sim_carrier_device) and the resolved learner device for tensor-native inference. Removed keys fail closed with migration hints, cuda no longer maps silently to MPS, and run_config.json records configured-to-resolved devices. The required unisim-core 1.7.25 enum support inventory and runtime parity guard are pinned (#2382). training.collector_tensor_device、manager_torch_device、env.tensor_runtime 与 env.tensor_runtime_device 已移除。请使用 training.sim_carrier_device（路由到 env.sim_carrier_device），并让 tensor-native 推理跟随已解析 learner 设备。移除键会带迁移提示 fail closed，cuda 不再静默映射 MPS，run_config.json 会记录“配置值 → 解析值”设备映射。所需 unisim-core 1.7.25 枚举支持清单与 runtime parity 守卫已固定。

  • The former unilab-rl distribution (import namespace uni_rl) is merged into the unilab package under unilab.rl (contracts / adapters / algos / runtime / logging layers), and the release surface converges to the single unilab distribution. The transitional uni_rl extra has been removed: legacy --extra uni_rl / pip install unilab[uni_rl] commands are no longer valid, and permanent import uni_rl support is not guaranteed. See ADR-0016 RL Reintegration Into unilab.rl And Single Distribution and the uni_rl.* → unilab.rl.* import-path mapping in Migrating from unilab-rl (uni_rl) (#2372). 原 unilab-rl distribution（import namespace uni_rl）并入 unilab 包的 unilab.rl（contracts / adapters / algos / runtime / logging 分层）， 发行面收敛为单一 unilab distribution。过渡期 uni_rl extra 已移除， 旧 --extra uni_rl / pip install unilab[uni_rl] 命令不再有效，且不承诺 永久支持 import uni_rl。决策见 ADR-0016，uni_rl.* → unilab.rl.* 的 import 路径映射见迁移页 从 unilab-rl（uni_rl）迁移（#2372）。

  • Removed the collector CUDA-graph public lifecycle and graph-named completion contract without aliases or compatibility paths. Runtime code now consumes the neutral completion-v2 receipt (state.info["completion"]) while eager ordered visibility, producer validation, actual-operation waits, backend-owned physics graphs, and learner CUDA graphs remain in their owner layers. Each successful step publishes its current receipt, and an autoreset step publishes the reset boundary receipt that gates its post-reset observation carrier (#2359, #2358). 移除 collector CUDA graph 的公共 lifecycle 与 graph 命名 completion 契约， 不保留 alias 或兼容路径。运行时改用中性 completion-v2 receipt （state.info["completion"]），同时保留 eager 有序可见性、producer 校验、 按实际操作等待、backend 私有 physics graph 与 learner CUDA graph （#2359、#2358）。

Changed / 变更¶

  • Raised the required unisim-core pin to 1.8.2 for the base, Motrix, and SuperDex dependency profiles, and removed the issue-local editable UniSim source override. The published release supplies the restored packed-reset, Isaac semantic-boundary, and Motrix wxyz FrameQuat contracts. 基础、Motrix 与 SuperDex 依赖配置将 unisim-core 提升到 1.8.2，并移除 issue 本地的 editable UniSim source override。已发布版本提供恢复后的 packed-reset、Isaac 语义边界与 Motrix wxyz FrameQuat 契约。

  • training.collector_tensor_device now defaults to auto: MuJoCo HOST_BRIDGE training follows the learner device, so a CUDA learner receives CUDA Manager/TorchEnv carriers and CUDA inference transport without explicit overrides, while CPU and torch.mps (Metal Performance Shaders) learners keep the CPU carrier. Explicit cpu/cuda values are unchanged and win over auto. Existing MuJoCo configurations that relied on the previous cpu default with a CUDA learner now allocate one CUDA context per collector process on the learner GPU; pin training.collector_tensor_device=cpu to keep the previous topology (#2365). training.collector_tensor_device 默认值改为 auto：MuJoCo HOST_BRIDGE 训练跟随 learner 设备——CUDA learner 无需显式配置即可获得 CUDA Manager/TorchEnv carrier 与 CUDA inference transport，CPU 与 torch.mps （Metal Performance Shaders）learner 保持 CPU carrier。显式 cpu/cuda 语义不变且优先于 auto。原先在 CUDA learner 下依赖 cpu 默认值的 MuJoCo 配置，现在每个 collector 进程会在 learner GPU 上额外占用一个 CUDA context；如需保持原拓扑，请显式固定 training.collector_tensor_device=cpu（#2365）。

Fixed / 修复¶

  • Fixed capability-scoped Manager carrier routing for every in-process packed HOST_BRIDGE backend, not only MuJoCo. Explicit training.sim_carrier_device=cuda and the default auto routing now honor the public backend torch_devices declaration for Motrix, Drake, and SuperDex, while unsupported or unknown device declarations fail closed. Physics remains CPU-authoritative; this changes only public Manager carrier placement (#2401). 修复 Manager carrier 路由仅限 MuJoCo 的问题：显式 training.sim_carrier_device=cuda 与默认 auto 现在按公开的后端 torch_devices 声明作用于 Motrix、Drake 与 SuperDex 等全部 in-process packed HOST_BRIDGE 后端；未声明或不受支持的设备会 fail closed。物理仍 以 CPU 为权威，本修复只改变公共 Manager carrier 放置位置。

  • Fixed device-resident Manager sensor staleness and restored SAC g1_walk_flat policy quality across the newly adapted backends. Every compiled derived sensor now crosses its backend boundary on full and selected-reset reads; IsaacSim uses a task-wide finite floor with audited 50 m clone spacing; and IsaacGym clamps position targets to source MJCF joint bounds. Full 5000-iteration SAC runs recover Genesis/Newton/IsaacSim/IsaacGym rewards and episode lengths comparable with the MuJoCo-family baselines (#2387). 修复 device-resident Manager sensor 停滞问题，并恢复新适配后端在 SAC g1_walk_flat 上的策略质量。每个 compiled derived sensor 在 full 与 selected-reset 读取时都会重新跨越 backend 边界；IsaacSim 使用覆盖任务的 finite floor 并审计 50 m clone 间距；IsaacGym 将 position target clamp 到 source MJCF joint bound。四条 5000-iteration SAC 完整运行的 reward 与 episode length 已回到 MuJoCo-family baseline 区间（#2387）。

  • Off-policy replay timeout bootstrapping: a transition that returns terminated=True and truncated=True together is a true terminal and no longer bootstraps. The collector now writes the timeout-bootstrap eligibility mask (truncated & ~terminated) into the replay truncated column while dones keeps the terminated | truncated lifecycle semantics and done rows keep the real terminal observations; SAC/FlashSAC targets are unchanged in form and now correct for the overlap case (unilab_rl#29). 修复 off-policy replay 的 timeout bootstrap：同一 transition 同时返回 terminated=True 与 truncated=True 时是真正的终止，不再 bootstrap。 collector 现在把 timeout bootstrap 资格掩码（truncated & ~terminated） 写入 replay 的 truncated 列；dones 保持 terminated | truncated 的生命周期语义，done 行仍携带真实 terminal observation；SAC/FlashSAC 的 target 公式形式不变，overlap 情形结果修正（unilab_rl#29）。

  • Multi-term concatenated observations are again caller-owned: the Manager no longer publishes rotating internal output carriers through the default eager boundary, so observations retained by a transition consumer remain immutable across later steps (#2362). 多 term 拼接 observation 重新归 caller 所有：Manager 不再通过默认 eager boundary 发布轮换的内部 output carrier，因此 transition consumer 保留的 observation 不会在后续 step 中被改写（#2362）。

  • Restored the v1.3.5 MotionCommand empty-reset-mask semantics: an empty mask consumes no sampler RNG and performs no backend state write or packet ingestion (#2359). 恢复 v1.3.5 的 MotionCommand 空 reset mask 语义：空 mask 不消耗 sampler RNG，也不写 backend state 或摄取 packet（#2359）。

1.3.5 (2026-10-13)¶

Breaking changes / 破坏性变更¶

  • Completed the production Torch-runtime closeout: UniLab no longer imports, compiles, tunes, or requires Numba. The CPU motion command and kernels were removed, cpu_ids owns only Linux process affinity, and every G1 motion owner uses the device-resident MotionCommandCfg. Manager, env, and task runtime code uses Torch-authoritative carriers and rejects hidden Torch↔NumPy conversions; the cold NPZ MotionLoader is the only task-runtime NumPy leaf, while base owners confine legacy NumPy exchange to explicit adapter/reset-host boundaries (#2124, ADR-0015). Production Numba 实现与依赖已完整移除：UniLab 不再 import、编译、调优或 依赖 Numba。CPU motion command 与 kernels 已删除，cpu_ids 仅保留 Linux process affinity 语义，所有 G1 motion owner 均使用 device-resident MotionCommandCfg。Manager、env 与 task runtime 使用 Torch-authoritative carrier，并拒绝隐藏的 Torch↔NumPy 转换；cold NPZ MotionLoader 是 task runtime 唯一 NumPy leaf，base owner 只在显式 adapter/reset-host boundary 内消化 legacy NumPy 交换（#2124、ADR-0015）。

  • The Manager-Based reset lifecycle now fails closed unless the backend declares packed_reset. UniLab’s NumPy-authoritative reset composer and non-packed fallback were removed: reset-mode state, model-field, and mocap writes are composed through UniSim’s public packed transaction and committed once per lifecycle. UniLab no longer calls SimBackend.set_state_tensor_mask(); mapped-entity tensor commits remain an explicit migration boundary (#2275, #2280, #2289). Manager-Based reset lifecycle 现在要求 backend 声明 packed_reset，否则 fail closed。UniLab 侧 NumPy-authoritative reset composer 与 non-packed fallback 已删除：reset-mode 状态、模型字段与 mocap 写入通过 UniSim 公共 packed transaction 组合，并在每个生命周期恰好提交一次。UniLab 不再调用 SimBackend.set_state_tensor_mask()；mapped-entity tensor 提交仍是显式 迁移边界（#2275、#2280、#2289）。

  • The training seed contract moved from the unilab.utils.seed transition shim to its owner at unilab.training.seed, without a compatibility alias. unilab.training continues to re-export the owner-facing helpers. algo.seed now seeds only global Python and Torch RNGs, and random interactive playback samples actions with Torch (#2124, #2283). 训练 seed 契约已从 unilab.utils.seed 过渡 shim 迁移到 owner unilab.training.seed，且不保留兼容 alias。unilab.training 继续导出 owner-facing helper。algo.seed 现在只 seed 全局 Python 与 Torch RNG， 随机 interactive playback 改用 Torch 采样 action（#2124、#2283）。

  • Removed the unilab.utils.rotation transition shim without a compatibility alias. Base-owner host math moved to unilab.base.rotation, while motion NPZ continuity and angular-velocity conversion now live inside the cold MotionLoader owner. 过渡 shim unilab.utils.rotation 已移除且不保留兼容 alias。base-owner host 数学迁移到 unilab.base.rotation；motion NPZ 连续性与角速度转换则 收进 cold MotionLoader owner 内部。

Added / 新增¶

  • Added backend tensor-runtime diagnostics. TorchEnv serializes the public backend diagnostics, training records them in runtime_manifest.backend_diagnostics, and direct PPO runs publish the same payload as top-level backend_diagnostics in run_summary.json; unavailable backends and probe failures are recorded explicitly (#2278, #2298). 新增 backend tensor-runtime diagnostics。TorchEnv 会序列化公共 backend diagnostics，训练将其记录到 runtime_manifest.backend_diagnostics，direct PPO run 会在 run_summary.json 顶层发布同一 payload；backend 不支持或探测失败都会显式 记录（#2278、#2298）。

Changed / 变更¶

  • Manager terms and tasks consume semantic, packed tensor state views for joint, body, root, contact, height, and sensor data. Legacy NumPy backend methods are no longer UniLab runtime APIs, and Entity host exchange is confined to the backend adapter boundary (#2276, #2277). Manager term 与 task 改为消费 joint、body、root、contact、height 与 sensor 数据的 semantic packed tensor view。legacy NumPy backend 方法不再是 UniLab runtime API，Entity host 交换收进 backend adapter 边界 （#2276、#2277）。

  • Selected reset execution replaced dynamically materialized row carriers with fixed-width packed masks. Commands, events, metrics, observations, terminations, curricula, and task state implement explicit mask-reset boundaries, commit only touched rows, and preserve active state elsewhere (#2285, #2288). selected reset 执行以 fixed-width packed mask 取代动态物化 row carrier。 command、event、metric、observation、termination、curriculum 与 task state 均实现显式 mask-reset 边界，只提交被写入的行，并保留其他行的 active 状态 （#2285、#2288）。

  • UniSim now owns packed reset composition: selected-row device qpos/qvel staging, selected-column merges, committed model-field baselines, startup baseline promotion, selected mocap staging, and the single public commit boundary. The composer is cached per declared device and its baseline persists across resets (#2275). UniSim 现在拥有 packed reset composition：selected-row device qpos/qvel staging、选中列合并、已提交模型字段 baseline、startup baseline 提升、 selected mocap staging，以及唯一公共提交边界。composer 按声明 device 缓存，baseline 跨 reset 持久（#2275）。

  • Required runtime dependencies moved to unisim-core>=1.7.17 and unilab-rl==1.4.12; the default and ROCm dependency profiles are aligned (#2281, #2299, #2301). 必需运行时依赖升级为 unisim-core>=1.7.17 与 unilab-rl==1.4.12； default 与 ROCm dependency profile 已对齐（#2281、#2299、#2301）。

Fixed / 修复¶

  • Fixed MuJoCo reset model-field DR commits through the host bridge, including startup randomization baselines (#2122, #2123). 修复 MuJoCo reset 模型字段 DR 经 host bridge 的提交，包括 startup randomization baseline（#2122、#2123）。

  • Fixed canonical off-policy packed-reset paths: root and motion payloads are normalized to contiguous float32 tensors, owner-subset commands track their actual fixed-width write mask while preserving unwritten active rows, and SAC MuJoCo PD gains compose as final kp/kd model fields instead of silently skipping randomization (#2296, #2300). 修复典型 off-policy packed-reset 路径：root 与 motion payload 归一化为 contiguous float32 tensor，owner-subset command 记录实际 fixed-width 写入 mask 并保留未写入的 active rows，SAC MuJoCo PD gain 以最终 kp/kd 模型字段 组合，而不是静默跳过随机化（#2296、#2300）。

  • Fixed motion NPZ body-column selection by local IDs, CUDA Manager carrier placement, and G1 reset-row observation boundaries (#2124, #2279, #2303). 修复按 local ID 选择 motion NPZ body column、CUDA Manager carrier placement， 以及 G1 reset-row observation 边界（#2124、#2279、#2303）。

1.3.4 (2026-10-10)¶

Breaking changes / 破坏性变更¶

  • The Manager-Based runtime is now tensor-only: NpEnv and NpEnvState were removed, TorchEnv is the sole environment lifecycle base, and Manager state, observations, rewards, terminations, commands, events, metrics, and recorder carriers use Torch tensors. Hot-path step/reset inputs no longer accept NumPy arrays or perform hidden host conversion (ADR-0011, ADR-0012). Manager-Based 运行时改为 tensor-only：删除 NpEnv / NpEnvState， TorchEnv 成为唯一环境生命周期基类；Manager 的状态、观测、奖励、终止、 command、event、metric 与 recorder carrier 均使用 Torch tensor。热路径 step/reset 不再接受 NumPy 输入，也不再做隐藏 host 转换（ADR-0011、 ADR-0012）。

  • Removed the production Numba implementation and dependency: the CPU motion command and its kernels were removed, cpu_ids now owns only Linux process affinity, and all G1 motion owners use the device-resident MotionCommandCfg. Manager/env runtime packages reject NumPy imports and hidden Torch↔NumPy conversions; the cold NPZ MotionLoader remains the only task-runtime NumPy leaf, while base owners consume legacy NumPy formats only in explicit adapter/reset-host boundaries (#2124, ADR-0015). 移除 production Numba 实现与依赖：删除 CPU motion command 和 kernels， cpu_ids 仅保留 Linux process affinity 语义，所有 G1 motion owner 均使用 device-resident MotionCommandCfg。Manager/env runtime package 禁止 NumPy import 与隐藏 Torch↔NumPy 转换；cold NPZ MotionLoader 仍是 task runtime 唯一 NumPy leaf，base owner 只在显式 adapter/reset-host boundary 内消化 legacy NumPy format（#2124、ADR-0015）。

  • The training-entry seed contract no longer mutates the legacy global NumPy RNG; algo.seed seeds global Python and Torch RNGs only. Random interactive playback also samples its actions with Torch instead of np.random.uniform. This removes the last environment-owned global NumPy RNG semantics from training (#2124). 训练入口 seed 契约不再修改 legacy 全局 NumPy RNG；algo.seed 只 seed 全局 Python 与 Torch RNG。随机 interactive playback 也改用 Torch 采样 action，不再调用 np.random.uniform。该变更移除训练中最后一个 environment-owned 全局 NumPy RNG 语义（#2124）。

  • The transition-shim module unilab.utils.rotation was removed without a compatibility alias. Its base-owner host math moved to unilab.base.rotation, while motion NPZ continuity and angular-velocity conversion now live inside the cold MotionLoader owner. 过渡 shim unilab.utils.rotation 已移除且不保留兼容 alias。base-owner host 数学迁移到 unilab.base.rotation；motion NPZ 连续性与角速度转换则 收进 cold MotionLoader owner 内部。

  • Production training now enters through the sole Manager-Based factory and the scoped tensor backend set. Retired task owners, the WarpSAC config tree, and task-owned direct training environment classes were removed; fused task components remain Manager-owned terms rather than alternate environments (#2071, #2072, ADR-0012). 生产训练统一进入唯一的 Manager-Based factory 与 scoped tensor backend 集。 退役 task owner、WarpSAC 配置树和 task-owned direct environment class 均已 移除；融合任务组件保持为 Manager-owned term，而不是另一套环境类。

  • Required runtime dependencies moved to unisim-core>=1.7.15, unilab-rl==1.4.11, and mjbatch-uni~=0.2.5; SAC uses the upstream SAC learner naming (algo_log_name=sac) (#2071, #2074, #2112, #2115). 必需运行时依赖升级为 unisim-core>=1.7.15、unilab-rl==1.4.11、 mjbatch-uni~=0.2.5；SAC 使用上游 SAC learner 命名 （algo_log_name=sac）。

Added / 新增¶

  • Added a Manager-owned selected-reset lifecycle: tensor reset rows, an owner reset transaction, reset-row observation publication, device-resident reset randomization negotiated through device_reset_randomization, and startup-mode body mass/COM randomization with committed baseline promotion. 新增 Manager-owned selected-reset 生命周期：tensor reset row、owner reset transaction、reset-row observation publication、通过 device_reset_randomization 协商的 device-resident reset DR，以及带已提交 baseline promotion 的 startup-mode body mass/COM DR。

  • Added scene-owned packed tensor reads for entity joint, body, and named sensor state; Manager terms consume validated device views, stable aggregate views, and backend-declared DEVICE_RESIDENT sensor inventories instead of hardcoded backend tables. Missing required device sensors fail closed. 新增 scene-owned packed tensor read：覆盖 entity joint/body/named sensor 状态；Manager term 消费经过校验的 device view、稳定 aggregate view 与后端 声明的 DEVICE_RESIDENT sensor inventory，而不是硬编码后端表。缺失的必需 device sensor 会 fail closed。

  • Added Manager-owned Torch RNG and deterministic seed/reset behavior for observation noise, commands, events, impulses, and selected reset. Device noise, temporal/delay state, and scalar sensor observation carriers are tensor-native. 新增 Manager-owned Torch RNG，覆盖观测噪声、command、event、impulse 与 selected reset 的 seed/reset 行为。噪声、temporal/delay 状态和标量 sensor observation carrier 均为 tensor-native。

  • Added the CUDA MPS single-rank execution-sharing mode and the user-owned uni-cumps CLI (status, doctor, start, stop, env). Training requests sharing explicitly with training.cuda_process_sharing=mps and validates a recorded daemon before construction; it never silently starts or stops a host service (ADR-0013, ADR-0014, #2065, #2069, #2085). 新增 CUDA MPS single-rank execution-sharing 模式与用户拥有的 uni-cumps CLI（status / doctor / start / stop / env）。训练必须通过 training.cuda_process_sharing=mps 显式请求，并在构造前校验已记录 daemon； 训练进程不会隐式启动或停止 host 服务（ADR-0013、ADR-0014）。

  • Added tensor-runtime production soak tooling, replay-ingress diagnostics, abnormal-shutdown evidence, schema/bounds consumption, tensor NaN guards, and the production guide for the scoped G1 Motion Tracking / FlashSAC / MJWarp path. 新增 tensor-runtime 生产 soak 工具、replay-ingress 诊断、异常退出证据、 schema/bounds 消费、tensor NaN guard，以及 scoped G1 Motion Tracking / FlashSAC / MJWarp 路径的生产指南。

  • Added opt-in off-policy training resume (algo.resume=true), explicit playback checkpoint selection, FlashSAC policy_before_critic, learner whole-cycle CUDA Graph controls, and grouped terminal metrics with bounded width tiers. 新增 opt-in off-policy 训练续训（algo.resume=true）、显式 playback checkpoint 选择、FlashSAC policy_before_critic、learner whole-cycle CUDA Graph 控制，以及带宽度分层的分组终端指标。

  • Added generic motion-tracking capabilities retained for downstream task packages: universal combo rewards, optional motion NPZ torque fields, tensor motion sampler/carriers, initialized physical action targets with public tensor_target, Gaussian-noise clamp, recursive hashable keys for shared cross-group observation terms, and MJWarp set_state_tensor benchmark timings/profile syntax. 新增供下游任务包复用的 generic motion-tracking 能力：universal combo reward、可选 motion NPZ torque 字段、tensor motion sampler/carrier、确定性 初始化且公开 tensor_target 的物理 action target、Gaussian noise clamp、 跨组共享 observation term 的递归 hashable key，以及 MJWarp set_state_tensor benchmark timing/profile 语法。

Changed / 变更¶

  • Reduced Manager host boundaries through packed reads, stable device views, fused action/reward/termination/observation/reset kernels, device-side samplers and RNG, cached tensor bounds, delayed reward host publication, and phase-level update-state/reset timing attribution. 通过 packed read、稳定 device view、融合 action/reward/termination/ observation/reset kernel、device-side sampler 与 RNG、缓存 tensor bounds、 延迟 reward host publication，以及 update-state/reset 的阶段级 timing attribution，减少 Manager host boundary。

  • MuJoCo remains the canonical HOST_BRIDGE backend. Its default Manager carrier stays on CPU even when a learner resolves to CUDA; an indexed CUDA collector carrier remains an explicit training.collector_tensor_device=cuda request. Breaking changes / 破坏性变更¶

  • Playback overlays now use typed per-environment DebugPrimitive values; the old extra_data_getter marker-array API is removed. 回放 overlay 改用类型化 per-environment DebugPrimitive；旧的 extra_data_getter marker-array API 已移除。

  • Removed downstream-specific tasks. Go2 arm manipulation/HIM-PPO moved to legged-manipulation_unilab, and Sharpa in-hand/HORA moved to the dedicated sharpa_rl_unilab repository (#1547). Their task configs, assets, scripts, compatibility imports, and core-owned helpers were removed from UniLab. The historical 1.2.0 label is retained, but these removals are compatibility-breaking; consumers should use the coordinated external repository commits. 移除下游专属任务。 Go2 机械臂操作/HIM-PPO 迁移到 legged-manipulation_unilab， Sharpa in-hand/HORA 迁移到专用 sharpa_rl_unilab 仓库（#1547）。相关任务 配置、资产、脚本、兼容导入和核心内专属 helper 已从 UniLab 移除。历史版本号 1.2.0 保持不变，但这些移除具有兼容性破坏；使用方应固定配套的外部仓库提交。

Added / 新增¶

  • SuperDex integration. Added the optional superdex extra, initial FR3 joint-target and Go2 joystick owners, native persistent CPU workers with rank-owned CPU partitions, and the FR3 bot asset download from Hugging Face (#1533, #1534). Published SuperDex wheels replace the temporary source build on CPython 3.12/3.13 Linux x86_64. FR3 playback is interactive-only because its .superdex_bot has no MJCF visual model; Go2 also supports recorded video playback. SuperDex 集成。 新增可选 superdex extra、首批 FR3 joint-target 与 Go2 joystick owner、带 rank-owned CPU partition 的原生持久 CPU worker，以及 来自 Hugging Face 的 FR3 bot 资产下载（#1533、#1534）。在 CPython 3.12/3.13 Linux x86_64 上，已发布的 SuperDex wheel 取代临时源码编译。FR3 资产 .superdex_bot 没有 MJCF visual model，因此只支持交互回放；Go2 另支持录制视频回放。

  • Third-party owner contracts. Entity/reset transactions support additional geom and joint-parameter writes, explicitly bound fixed mocap bodies, and versioned training-progress export/import for downstream community packages such as Wuji. Playback uses typed DebugPrimitive overlays and exposes an embeddable SnapshotPlaybackSession for custom evaluation loops. 第三方 owner contract。 Entity/reset transaction 支持更多 geom 与 joint 参数写入、显式绑定的固定 mocap body，以及供 Wuji 等下游社区包使用的版本化 training-progress 导出/导入。回放改用类型化 DebugPrimitive overlay，并暴露可 嵌入自定义评估循环的 SnapshotPlaybackSession。

Changed / 变更¶

  • Compatibility updates. Requires unisim-core>=1.2.0, pins unilab-rl==1.2.0, and updates the ROCm lock profile. This carries the shared backend, collector, and playback contracts used by the new owners. Because the SuperDex extra can also bring plain MuJoCo, sim=mujoco now checks the mujoco_uni runtime binding. 兼容性更新。 要求 unisim-core>=1.2.0，固定 unilab-rl==1.2.0，并更新 ROCm lock profile。这承载新 owner 所需的共享 backend、collector 与 playback contract。由于 SuperDex extra 也可能带入普通 MuJoCo，sim=mujoco 现在会检查 mujoco_uni runtime binding。

Fixed / 修复¶

  • PPO action-standard-deviation logging now uses the current policy distribution, including state-dependent action scales. Nested play-profile merging also preserves unrelated fields and sibling observation terms when a partial override is applied. PPO action standard deviation 日志现在读取当前 policy distribution，可正确覆盖 state-dependent action scale。嵌套 play profile 合并时，局部 override 也会保留 未相关字段和 sibling observation term。

1.1.0 (2026-09-06)¶

  • Added the Newton backend owner path and native ViewerGL playback, including the initial G1 walk PPO/SAC owners (#1509, #1511). 新增 Newton backend owner 路径与原生 ViewerGL 回放，包括首批 G1 walk PPO/SAC owner（#1509、#1511）。

  • Fixed multi-GPU routing for spawned data-parallel collectors: rank-local backend devices are selected before CUDA/runtime initialization, including Genesis on non-zero physical GPUs and Newton’s rank-local device override. 修复 spawn data-parallel collector 的多 GPU 路由：在 CUDA/runtime 初始化前选择 rank-local backend 设备，包括非零物理 GPU 上的 Genesis 以及 Newton 的 rank-local device override。

  • Added third-party task-package discovery through the unilab.tasks entry point group and generic interval domain-randomization dispatch (#1501, #1504). 新增通过 unilab.tasks entry-point group 发现第三方 task package 的能力， 以及通用 interval domain-randomization dispatch（#1501、#1504）。

  • Updated the shared runtime contracts: unisim-core>=1.1.3, MuJoCo/MJWarp extras on the MuJoCo 3.11 line, mujoco-uni-runtime==0.5.0, and the matching ROCm profile. Go1 mesh assets also moved to the shared Hugging Face asset flow and out of the published wheel/sdist. 更新共享 runtime contract：unisim-core>=1.1.3、MuJoCo/MJWarp extra 对齐 MuJoCo 3.11、mujoco-uni-runtime==0.5.0 以及配套 ROCm profile。Go1 mesh 资产同时迁移到共享 Hugging Face asset 流程，并从发布的 wheel/sdist 移除。

  • Expanded the bilingual backend evidence, installation, sim-to-sim, and project-rationale documentation. 扩展了 backend 证据、安装、sim-to-sim 与项目定位的双语文档。

1.0.0 (2026-09-04)¶

  • Promoted the 0.1 architecture to the first stable package line: consume the production unilab-rl==1.0.0 release instead of the 0.2 TestPyPI line, broaden the exact Torch pins to ranges below 2.12 (with the Linux aarch64 floor at 2.9), and publish canonical project metadata and links. 将 0.1 架构提升为首个稳定包版本线：消费生产版 unilab-rl==1.0.0 而不是 0.2 TestPyPI 版本，将精确 Torch 钉版放宽到低于 2.12 的范围（Linux aarch64 下限为 2.9），并发布规范项目元数据与链接。

  • Narrowed the packaged task surface: non-production MicroDuck and T800 task families moved to downstream ecosystem packages, and unused large motion files were removed. The manager-based runtime and production task owners introduced in 0.1.0 remain the supported API. 收窄打包任务面：非生产 MicroDuck 与 T800 task family 迁移到下游生态包， 并移除未使用的大 motion 文件。0.1.0 引入的 manager-based runtime 与生产 task owner 仍是受支持 API。

  • Fixed event-curriculum velocity updates to re-read the live velocity range and fail closed when newly activated angular axes were not bound at construction. Reset terms can also read root poses already staged in the same transaction. 修复 event-curriculum velocity 更新：每次事件应用都会重新读取当前 velocity range；构造期未绑定的角度轴被激活时会 fail closed。reset term 也可以读取同一 transaction 中已 stage 的 root pose。

  • Added tag-based trusted PyPI publishing with tag/version and successful-CI checks, distribution metadata validation, wheel installation, and an import smoke test. 新增基于 tag 的 PyPI trusted publishing，包含 tag/版本与成功 CI 校验、发行 元数据检查、wheel 安装和导入 smoke test。

0.1.0 (2026-09-04)¶

  • First functional PyPI package. UniLab moved to the NumPy Manager-Based API with Hydra task owners for observations, actions, rewards, terminations, events, commands, curricula, and metrics; legacy monolithic environments were removed (#1042). 首个可实际使用的 PyPI 包。UniLab 迁移到 NumPy Manager-Based API，使用 Hydra task owner 声明 observation、action、reward、termination、event、command、 curriculum 与 metrics；旧的一体化 environment 已移除（#1042）。

  • Physics adapters moved behind unisim-core>=0.1.14 (unisim) with MuJoCo, Motrix, MJWarp, Drake, Genesis, IsaacGym, and IsaacSim identities. RL algorithms, runners, collectors, IPC, and training logs moved behind unilab-rl==0.2.0 (uni_rl), preserving the package boundary that prevents learner code from importing UniLab. 物理适配器迁移到 unisim-core>=0.1.14（unisim），覆盖 MuJoCo、Motrix、 MJWarp、Drake、Genesis、IsaacGym 与 IsaacSim。RL 算法、runner、collector、 IPC 与训练日志迁移到 unilab-rl==0.2.0（uni_rl），保持 learner 代码不得 导入 UniLab 的包边界。

  • The unified train, eval, and demo CLI covers PPO, APPO, SAC, TD3, and FlashSAC workflows; robot/scene/motion assets and demo checkpoints download from Hugging Face on first use. HORA and HIM-PPO remained script-level workflows at this release. 统一 train、eval 与 demo CLI 覆盖 PPO、APPO、SAC、TD3 与 FlashSAC 工作流；robot/scene/motion 资产和演示 checkpoint 首次使用时从 Hugging Face 下载。HORA 与 HIM-PPO 在该版本仍是脚本级工作流。
