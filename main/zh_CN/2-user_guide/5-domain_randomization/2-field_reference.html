字段参考¶

本页是 src/unilab/envs/mdp/events.py 中域随机化（DR）event term 的字段级 配置参考，与 域随机化（审计各注册任务声明了哪些 term）和 配置（说明 owner YAML 的选择方式）互补。下文所有签名、 默认值与取值线索均来自源码或 src/unilab/conf/ 下的 owner YAML，不从设计 意图推断任何内容。

DR term 运行在三个生命周期类别下（见 域随机化 的生命周期概述）：

  • construction：固定 model/tool identity，在 env.fixed_model_variants 上声明；本页没有任何 event term 属于该类别。

  • reset：mode: reset 的 event term 在每次 episode reset 时采样，并经 backend 持有的 packed reset transaction 一次性提交。mode: startup 是 reset 生命周期的可选变体：初始化时采样一次，之后回放冻结的逐环境取值。

  • interval：mode: interval 的 event term 在 step 之间按采样计时器施加 扰动；mode: step 每个 step 都触发，由 term 自行管理力的生命周期。

Backend 适用性¶

字段 × backend 的精确矩阵由外部包 unisim-core 持有 （DomainRandomizationCapabilities.supported_reset_terms / supported_interval_terms），无法从本仓库逐字段确认，因此本页刻意不给出 该矩阵。有两条规则始终成立：

  1. 所选 backend 未声明支持的 term 在构造期 fail closed；不存在过滤或静默 回退。

  2. Owner YAML 按 backend 分文件 （src/unilab/conf/<algo>/task/<task>/<backend>.yaml）。某个 backend 不支持的 term 在该 backend 的 owner 中置为 null，共享 base owner 为 其余 backend 保留它。

仓库内的该模式示例：src/unilab/conf/ppo/task/g1_walk_flat/motrix.yaml 与 .../mjwarp.yaml 把 pd_gains 置为 null，而 MuJoCo owner 保留 kp/kd 随机化；src/unilab/conf/sac/task/g1_motion_tracking/genesis.yaml 把 foot_friction 置为 null，注释记录了 Genesis 没有逐环境 friction API。 最完整的 owner 实例（mass、COM、gravity、push）是 src/unilab/conf/flashsac/task/go2_joystick_flat/mujoco.yaml 的 events: 段。

通用参数族¶

下列参数在多个 term 间复用。下方各 term 的表只列出其构造函数实际接受的 参数；未知 param 会在构造期被拒绝。

  • asset_cfg（SceneEntityCfg）：选择 entity 及其组件。name 必填（场景 实体名，例如 robot）；组件通过 body_names/body_ids、 joint_names/joint_ids、geom_names/geom_ids 或 actuator_names/actuator_ids 选择。*_names 字段接受正则字符串； *_ids 字段默认为”全部”。多数 term 默认为 SceneEntityCfg("robot") （整台机器人）。

  • distribution："uniform"（默认）、"log_uniform"（bounds 必须为正） 或 "gaussian"（range 读作 (mean, std)，std 非负）。pd_gains 只接受 uniform/log_uniform。

  • operation：采样值与 backend 声明的默认值的组合方式："add" → default + sample，"scale" → default * sample，"abs" → 采样值 直接覆盖默认值。默认值因 term 而异，见各表。

  • range 形状约定：标量对 [lo, hi]（如 kp_range、 mass_distribution_params）；按轴字典 {x: [lo, hi], ...} （com_range、pose_range、velocity_range，省略的键默认为 (0, 0)）； 宽度为 3 的 [[lo_x, lo_y, lo_z], [hi_x, hi_y, hi_z]] （gravity_distribution_params）；model-field term 的 ranges 还可以是 作用于所有选中轴的扁平 pair、按轴索引的字典，或 regex → pair 的字典 （对选中的 geom/joint 名做 fullmatch；每个 pattern 至少匹配一个名字且 不得重叠）。

外层的 term 块（func、mode、interval_range_s、is_global_time、 min_step_count_between_reset、params）是一个 EventTermCfg； interval_range_s 与 is_global_time 位于 term 上，不在 params 内。 mode: interval 时 interval_range_s 必填；is_global_time: true 让所有 环境共用一个计时器。

reset_root_state_uniform_fused¶

参数与语义同 reset_root_state_uniform （unilab.envs.mdp.reset_root_state_uniform_fused），但在一张编译后的 Torch 图中为所有环境采样，并要求 CUDA tensor runtime 上的 Manager RNG。 backend owner 通过替换现有 reset_root_state_uniform term 的 func 来 启用，例如 src/unilab/conf/ppo/task/g1_walk_flat/mjwarp.yaml。

reset_scene_to_default¶

unilab.envs.mdp.reset_scene_to_default。无参数。把所有已物化的场景实体 重置为 backend 默认 qpos/qvel；base owner 将其声明为第一个 reset term。

unilab.envs.mdp.skip_scene_reset。无参数。空操作 reset 钩子，作为 MJWarp 的规范 reset 场景 term：backend owner 把继承来的 reset_scene_to_default term 的 func 换成它（例如 src/unilab/conf/ppo/task/g1_walk_flat/mjwarp.yaml、 src/unilab/conf/ppo/task/go2_joystick_flat/superdex.yaml）。

最小配置示例¶

DR term 声明在所选 backend owner 的 events: 段中，文件位于 src/unilab/conf/<algo>/task/<task>/<backend>.yaml —— 例如 src/unilab/conf/flashsac/task/go2_joystick_flat/mujoco.yaml，以下示例 即改编自该文件的配置段：

env:
  events:
    randomize_rigid_body_mass:
      func: unilab.envs.mdp.randomize_rigid_body_mass
      mode: reset
      params:
        asset_cfg:
          _target_: SceneEntityCfg
          name: robot
          body_names: base
        mass_distribution_params: [-1.5, 1.5]
        operation: add
        recompute_inertia: false
    randomize_rigid_body_com:
      func: unilab.envs.mdp.randomize_rigid_body_com
      mode: reset
      params:
        asset_cfg:
          _target_: SceneEntityCfg
          name: robot
          body_names: base
        com_range:
          x: [-0.05, 0.05]
    push_by_setting_velocity:
      func: unilab.envs.mdp.push_by_setting_velocity
      mode: interval
      interval_range_s: [15.0, 15.0]
      is_global_time: true
      params:
        velocity_range:
          x: [-1.0, 1.0]
          y: [-1.0, 1.0]
          z: [-0.5, 0.5]
          roll: [0.0, 0.0]
          pitch: [0.0, 0.0]
          yaw: [0.0, 0.0]

用 CLI 选择 backend —— uv run train --algo <algo> --task <task> --sim <backend> —— 并把 backend 未声明支持的 term 从其 owner 中移除（或置为 null），因为不支持的 term 会在构造期 fail closed。

常见问题¶

如何给 Go2 加 friction 随机化？ 在支持该能力的 backend owner 中声明一个 mode: reset 的 geom_friction term，用 geom_names 正则选中足部 geom。仓库内的模板是 SAC G1 MuJoCo owner：src/unilab/conf/sac/task/g1_motion_tracking/mujoco.yaml 选中 geom_names: "^(left|right)_foot[1-7]_collision$"，并用 ranges: [0.3, 1.2]、operation: abs、shared_random: true。请对照 Go2 模型的 geom 名写出等价 pattern。geom friction 是 backend 声明的能力：同一 任务的 Genesis owner 因 Genesis 没有逐环境 friction API 而把 foot_friction 置为 null，因此不要在未声明该能力的 backend 上启用此 term。

mass 参数的单位是什么？ 使用模型的 body 质量单位 —— 本仓库的 MuJoCo MJCF 机器人为千克。采样值 经 operation 与 backend 声明的默认质量组合：add 加千克（FlashSAC Go2 owner 给 base 加 ±1.5 kg），scale 乘无量纲因子（SAC G1 Genesis owner 把 pelvis/torso_link 缩放 [0.9, 1.1]），abs 直接设绝对千克数。 结果按 min_mass（默认 1e-6）做下限截断。

Motrix 不支持 gravity 时，如何写一份 Motrix 与 MuJoCo 都能跑的 owner YAML？ 按 配置，gravity reset 随机化目前仅 MuJoCo 可用； MotrixBackend 只声明支持 base_mass_delta、base_com_offset、kp、 kd 与 interval push（见 域随机化）。共享 term 留在任务的 base.yaml，只在 mujoco.yaml 声明 randomize_physics_scene_gravity；如果共享 base 已声明它，就在 motrix.yaml 中设置 randomize_physics_scene_gravity: null —— 与 src/unilab/conf/ppo/task/g1_walk_flat/motrix.yaml 和 .../mjwarp.yaml 中 pd_gains: null 的模式相同。若让 Motrix 保留该 term，构造期会 fail closed 而不是被跳过。

这些 term 背后的 payload 级契约见 Domain Randomization Contract。
